# Spec: Outfit Color Matcher (เว็บไซต์จับคู่สีเสื้อผ้า)

> สเปกทางวิศวกรรมที่แปลงจากสรุปหลัง Grill ให้พร้อมนำไปสร้าง (implementation-ready)
> ขอบเขตส่งมอบรอบแรก = เฟส 1; เฟส 2-3 ระบุโครงไว้ให้เห็นทิศทาง
> รูปแบบผลิตภัณฑ์: เว็บหน้าเดียว (single-page website) เป็น Claude Artifact + ไฟล์ .html

## 1. ปัญหาและเป้าหมาย
- **ปัญหา:** คนมีเสื้อผ้าอยู่แล้วแต่ไม่รู้จะจับคู่สีอย่างไร และไม่อยากคิดเองทีละชิ้น
- **เป้าหมาย:** เว็บเป็นฝ่ายเสนอชุดที่สีเข้ากันให้ทันที พร้อม "คำแนะนำอิงทฤษฎีสี" และ "สัดส่วนสีของลุค" โดย **ไม่ตัดสิน/ให้คะแนน**การแต่งตัว
- **ผลลัพธ์ที่วัดได้:** เปิดเว็บครั้งแรกเห็นชุดแนะนำได้ทันที (จากตัวอย่าง), ผู้ใช้เพิ่มเสื้อผ้าจริงแล้วได้ชุดจากตู้ตัวเอง

## 2. Non-goals (สิ่งที่จงใจไม่ทำ)
- ไม่มีระบบคะแนน/จัดเรตความสวย, ไม่วิจารณ์ผู้ใช้
- ไม่รองรับลายผ้า (1 ชิ้น = 1 สี)
- ไม่ใช้ backend / ไม่ล็อกอิน / ไม่ใช้ capability ใดๆ (localStorage ล้วน เพื่อแชร์ลิงก์สาธารณะได้)
- ไม่เรียก AI ตอบสด (คำแนะนำเป็น template)
- ไม่ทำ ฤดู/สภาพอากาศ/สภาพผิว ในรอบนี้ (Backlog)

## 3. ผู้ใช้และสถานการณ์หลัก
- **ผู้ใช้:** คนทั่วไปที่อยากได้ไอเดียแต่งตัวจากตู้ตัวเอง
- **สถานการณ์:** (1) "วันนี้แต่งอะไรดี" เลือกโอกาสแล้วรับชุด (2) อยากนำสีเอง (3) สำรวจ/วิเคราะห์ตู้ตัวเอง

## 4. สถาปัตยกรรมแกน: Color Matching Engine
เครื่องยนต์เดียวที่ทุกฟีเจอร์เรียกใช้ รับ constraint แล้วคืนชุดผลลัพธ์

### 4.1 นิยามสี (ฐานของทุกอย่าง)
- แปลง hex -> HSL
- **neutral:** ความอิ่มสี S < 20% (ค่าตั้งต้น ปรับได้) หรือความสว่าง L สุดขั้ว (ขาว/ดำ) => จัดเป็น neutral
- **warm/cool:** สีที่ไม่ใช่ neutral แยกด้วยองศา hue (warm ~ 0-60 และ 300-360, cool ~ 120-270 โดยประมาณ ปรับได้)
- **accent:** สี non-neutral ที่อิ่ม/สดพอ (S สูง)

### 4.2 ความสัมพันธ์ของสี (harmony rule ที่ตรวจได้)
ตรวจจากผลต่างองศา hue ระหว่างสี non-neutral ในลุค:
- monochrome: hue ต่างกันน้อยมาก
- analogous: ต่างกันราว 15-45 องศา
- complementary: ต่างกันราว 150-210 องศา
- triadic: กระจายราว 120 องศา
- neutral+accent: มี neutral เป็นส่วนใหญ่ + accent 1 สี
ถ้าเข้าได้หลาย rule เลือก rule ที่ "ชัดที่สุด" (ระยะใกล้ค่ากลางของ rule นั้นสุด)

**ข้อจำกัดที่ต้องซื่อสัตย์:** กฎมุม hue **เพิ่มโอกาสให้ชุดที่สุ่มออกมากลมกลืนภายใต้กฎที่กำหนด** ไม่ได้แปลว่าดูดีเสมอ เช่น complementary 180° จะสวยหรือไม่ยังขึ้นกับ saturation, lightness และบริบทของแต่ละชิ้น ดังนั้น engine จึงถ่วงด้วย contrast/สัดส่วน neutral (4.3) และคิดเชิง Color Role (4.7) ประกอบ ไม่ตัดสินจากมุม hue อย่างเดียว

### 4.3 การให้คะแนนเงียบเบื้องหลัง (internal เท่านั้น ไม่โชว์)
คะแนนภายในใช้ **เพื่อคัดและเรียงลำดับ**ว่าจะโชว์ชุดไหนก่อน ประกอบจาก:
- ความชัดของ harmony rule ที่จับได้
- ความต่างค่าสว่าง (contrast) อยู่ในช่วงที่อ่านง่าย (ไม่จมกันจนกลืน ไม่ตัดกันจนแสบ)
- สัดส่วนสีกลาง (มี neutral คุมโทนช่วยให้ลุคนิ่ง)
เก็บเป็น field `_harmony` ในผลลัพธ์ **ห้ามแสดงต่อผู้ใช้เป็นตัวเลข/เกรด**

### 4.4 สัดส่วนสีของลุค (ตัวเลขที่โชว์แทนคะแนน)
- **น้ำหนักตามหมวด (พื้นที่):** บน+ล่าง = ส่วนใหญ่ (60), นอก = รอง (30), รองเท้า/แอกเซสซอรี = เน้น (10)
- รวมสีตามน้ำหนักหมวดแล้วคำนวณ **% รายสี** (เช่น Navy 55 / Cream 30 / White 15)
- แต่ละสีถูกกำหนด **Color Role** ด้วย (ดู 4.7) แล้ว map เข้ากับ 60-30-10
- โชว์ทั้งสัดส่วน role และ % รายสี (ไม่ใช่คะแนนความดี-ด้อย)

### 4.5 คำแนะนำ (template อิงทฤษฎีสี)
- เลือกข้อความสำเร็จรูปจาก (rule ที่จับได้) + (สัดส่วน neutral/accent) เช่น
  - analogous: "โทนนี้เป็น analogous สีใกล้เคียงกัน ดูกลมกลืน"
  - neutral สูง: "มีสีกลางคุมโทน ลุคดูเรียบสะอาด"
  - accent เด่น: "มีสีเน้นหนึ่งจุด ช่วยให้ลุคไม่จืด"
- ข้อความเป็นเชิงบอกลักษณะ/แนะนำ ไม่ตัดสินถูก-ผิด

### 4.6 สองโหมดผลลัพธ์ (ตัวสลับหลักบนหน้าแนะนำ)
ทุกหน้าที่โชว์ผลแนะนำมี **ตัวสลับ 2 แบบ** อยู่ด้านบน ใช้ engine ตัวเดียวกันแต่ต่างที่ "แหล่งของสี":
- **โหมด "สีที่เราแนะนำ" (idea):** สร้างชุดสี/ลุคจากทฤษฎีสีล้วน **ลูกค้าไม่ต้องมีเสื้อผ้าจริง** แสดงเป็นสวอทช์สี + role 60-30-10 + คำแนะนำ (items เป็น null ได้ มีแต่สี)
- **โหมด "สีที่ลูกค้ามี" (wardrobe):** จับคู่จาก garment จริงในตู้ แสดงเป็นชิ้นเสื้อผ้าจริง + สัดส่วนสี + คำแนะนำ
- **ค่าเริ่มต้น:** ถ้าตู้มีของพอ (>=1 บน + 1 ล่าง) เปิดที่โหมด "สีที่ลูกค้ามี"; ถ้าตู้ยังไม่พอ เปิดที่โหมด "สีที่เราแนะนำ" อัตโนมัติ (ยังเห็นคุณค่าได้แม้ตู้ว่าง)
- ทั้งสองโหมดใช้ layout/สัดส่วน/คำแนะนำหน้าตาเดียวกัน ต่างแค่ items มี/ไม่มีของจริง

### 4.7 Color Role (หัวใจการจัดองค์ประกอบ)
engine ไม่ได้ถามแค่ "สี A กับ B ห่างกันกี่องศา" แต่ถามว่า **"สีนี้ควรทำหน้าที่อะไรในลุค"** โดยกำหนด role ให้ทุกสี:

```
Primary        (สีหลัก คุมโทนรวม, ~60%)
   ↓
Secondary      (สีรอง เสริมสีหลัก, ~30%)
   ↓
Neutral        (สีกลางถ่วงให้ลุคนิ่ง อยู่ได้หลายจุด)
   ↓
Accent         (สีเน้นจุดเดียว ดึงสายตา, ~10%)
```
ตัวอย่าง: `Navy -> Primary` / `Cream -> Secondary` / `White -> Neutral` / `Brown -> Accent`

**วิธีกำหนด role (จาก HSL + หมวด):**
- สีอิ่มต่ำ (neutral ตาม 4.1) => role **Neutral** (คุมไม่ให้ลุครก)
- สี non-neutral ที่ครองพื้นที่มากสุด (มักคือ บน/ล่าง) => **Primary**
- สี non-neutral รองลงมา ที่เข้ากับ Primary ตาม rule => **Secondary**
- สีสด/ตัดที่สุด บนพื้นที่เล็ก (รองเท้า/แอกเซส) => **Accent** (ควรมีอย่างมาก 1)

**กติกาองค์ประกอบที่ engine ยึด (map เข้า 60-30-10):**
- ทุกลุคควรมี Primary 1; Neutral ช่วยถ่วงได้เสมอ; **Accent ไม่เกิน 1** (มีหลาย accent = รก)
- ถ้าไม่มี neutral เลยและมีสีสดหลายตัว => ลด/เลี่ยงชุดนั้น (คิดเชิง role ไม่ใช่แค่มุม hue)
- โหมด "สีที่เราแนะนำ" สุ่มโดย **ไล่ตาม role**: เลือก Primary ก่อน -> หา Secondary ตาม rule -> เติม Neutral -> ใส่ Accent 1 (จึงคุมสัดส่วน 60-30-10 ได้ตั้งแต่ต้น)

## 5. Functional requirements + Acceptance criteria

### FR-0 ตู้เสื้อผ้า (Wardrobe) [เฟส 1]
เพิ่ม/แก้/ลบชิ้นเสื้อผ้า: ชื่อ, หมวด, สี(hex), รูป(ถ้ามี, <=2, ย่อเป็น data URL); ดึงสีจากรูปด้วย canvas (เฉลี่ยโซนกลางภาพ) เติมช่อง hex ที่แก้เองได้
- **AC1 (Given ตู้ว่าง, When เพิ่มชิ้นครบข้อมูล, Then) ** ชิ้นนั้นปรากฏเป็นชิปสีในตู้ และคงอยู่หลังรีเฟรช (localStorage)
- **AC2 (When อัปโหลดรูป) ** ช่อง hex ถูกเติมด้วยสีเด่นโดยประมาณ และผู้ใช้แก้ค่าได้ ค่าที่แก้คือค่าที่ถูกเก็บ
- **AC3 (When localStorage ถูกบล็อก) ** ยังเพิ่ม/ดูในเซสชันได้ และมีข้อความบอกว่าจะไม่ถูกบันทึกถาวร
- **AC4 (When แก้ไขชิ้นโดยไม่เลือกรูปใหม่) ** รูปเดิมคงอยู่

### FR-1 Today Outfit "วันนี้แต่งอะไรดี?" [เฟส 1, พระเอก]
เลือกโอกาส -> engine คัด/เรียงเงียบ -> โชว์แบตช์ 3-4 ชุด (วนลูปดูด้วย </>), ปุ่มแยก "เจนชุดใหม่" สร้างแบตช์ใหม่; แต่ละชุดมีสัดส่วนสี + คำแนะนำ; **มีตัวสลับ 2 โหมดด้านบน (ดู 4.6): "สีที่เราแนะนำ" / "สีที่ลูกค้ามี"**; แสดงแต่ละชุดเป็นกรอบสี่เหลี่ยมต่อหมวด (ดู 7B)
- **AC1** ถ้าตู้มีอย่างน้อย 1 บน + 1 ล่าง ต้องได้ชุด >= 1 ชุด
- **AC2** ทุกชุดที่โชว์ต้องมีบน+ล่างครบ (ห้ามโชว์ชุดขาดหมวดจำเป็น); นอก/รองเท้า/แอกเซสเสริมถ้ามี
- **AC3** ทุกชุดใช้ garment จริงจากตู้ (หรือชุดตัวอย่างที่ติดป้าย)
- **AC4** แต่ละชุดแสดงสัดส่วนสี (role 60-30-10 + %รายสี) และคำแนะนำ อย่างน้อย 1 ข้อความ; **ไม่แสดงคะแนน**
- **AC5** โอกาสมีผลต่อการเอนโทนสีเท่านั้น (Work/Dinner เอนเข้ม/นิ่ง, Party ยอม accent จัดขึ้น) ตรวจได้ว่าเปลี่ยนโอกาสแล้วชุด/ลำดับเปลี่ยนไปในทิศที่นิยาม
- **AC6** โชว์แบตช์ละ 3-4 ชุด; ปุ่ม `<` `>` วนลูปดูภายในแบตช์ (ไม่สร้างชุดใหม่เอง); ปุ่มแยก "เจนชุดใหม่" สร้างแบตช์ใหม่ 3-4 ชุดมาแทน (พยายามไม่ซ้ำแบตช์เดิม เท่าที่ combination มี)
- **AC7 (Given ตู้ไม่พอ เช่นไม่มีล่าง) ** ในโหมด "สีที่ลูกค้ามี" แสดงข้อความชวนเพิ่มชิ้นที่ขาด แทนการแนะนำมั่ว และยังสลับไปโหมด "สีที่เราแนะนำ" เพื่อดูไอเดียได้
- **AC8** มีตัวสลับ 2 โหมด (ดู 4.6); โหมด "สีที่เราแนะนำ" แสดงผลได้แม้ตู้ว่าง (สวอทช์สี ไม่มีของจริง), โหมด "สีที่ลูกค้ามี" ใช้ garment จริง; ค่าเริ่มต้นเลือกตามความพร้อมของตู้

### FR-2 Swap One Item [เฟส 2]
ในชุดหนึ่ง ล็อกชิ้นอื่น เปลี่ยนเฉพาะหมวดที่เลือก (เสื้อ/กางเกง/รองเท้า/นอก)
- **AC1** กดเปลี่ยนหมวดหนึ่ง ชิ้นหมวดอื่นไม่เปลี่ยน
- **AC2** ตัวที่เอามาแทนคือตัวถัดไปที่เข้ากันดีในหมวดนั้น (ตามคะแนนเงียบ); กดซ้ำวนตัวถัดไป
- **AC3** สัดส่วนสี + คำแนะนำอัปเดตตามชุดใหม่

### FR-3 Favorite Outfit [เฟส 2]
บันทึกชุดลง localStorage: Save / ตั้งชื่อ / Delete / Duplicate / เปิดแก้ไข (**สูงสุด 20 ชุด**, เก็บ snapshot สี+ชื่อ ไม่เก็บรูปในตัว favorite)
- **AC1** ชุดที่ Save คงอยู่หลังรีเฟรช; **AC2** Duplicate ได้สำเนาแยกแก้ได้; **AC3** Delete ลบเฉพาะชุดนั้น

### FR-4 Wardrobe Color Analysis [เฟส 3, จุดต่าง]
วิเคราะห์สีทั้งตู้: %รายสี, กลุ่ม Neutral/Cool/Warm/Accent (จาก HSL), insight + สีที่ช่วยเพิ่มการจับคู่
- **AC1** สัดส่วน % คำนวณจาก garments จริงในตู้
- **AC2** แยก Neutral/Color/Accent ได้ตามนิยาม 4.1
- **AC3** insight 1-3 ข้อจากกฎ threshold + template (เช่น neutral>70% -> ชวนเพิ่ม accent)
- **AC4** สีที่แนะนำ = สีที่เข้ากับสีฐานเด่นสุดในตู้แต่ยังขาด เขียนเชิง "เพิ่มตัวเลือกการจับคู่" ไม่ใช่บอกให้ซื้อ
- **AC5 (Given ข้อมูลน้อยเกินไป) ** บอกผู้ใช้ตรงๆ แทนการวิเคราะห์มั่ว

### FR-5 Color-first "วันนี้อยากใส่สีอะไร?" [เฟส 3]
เลือกสี (swatch หรือจากตู้) -> ล็อกเป็น main -> engine หาส่วนที่เหลือรอบสีนั้น
- **AC1** ทุกชุดผลลัพธ์มีสีที่ล็อกเป็นองค์ประกอบหลัก; **AC2** โชว์สัดส่วนสี + คำแนะนำ

### FR-6 Outfit Generator [เฟส 3]
Style + Color + สวิตช์ Use my wardrobe ซึ่งก็คือ **สองโหมดเดียวกับ 4.6**: เปิด = "สีที่ลูกค้ามี" (จากตู้จริง), ปิด = "สีที่เราแนะนำ" (palette จากกฎสีสดๆ) โดย Outfit Generator เพิ่มตัวกรอง Style/Color เข้ามาบนโหมดเดิม
- **AC1** โหมด wardrobe ใช้ garment จริง; **AC2** โหมด idea สร้าง palette ตาม rule โดยไม่ต้องมีของจริง แสดงเป็นสวอทช์ + สัดส่วน 60-30-10

## 6. Data model
- **Garment:** `{ id, name, category, color(hex), photo?(dataURL), isExample? }`
- **Category:** top | bottom | outer | shoes | accessory (ชุดครบ = top+bottom, ที่เหลือเสริม)
- **Occasion:** everyday | university | work | cafe | dinner | party | unspecified (map เป็นการปรับโทนเท่านั้น)
- **Outfit (ผลลัพธ์):** `{ sourceMode:'idea'|'wardrobe', items:{top,bottom,outer?,shoes?,accessory?}|null, proportion:{main,secondary,accent}, colorBreakdown:[{hex,pct,role:'primary'|'secondary'|'neutral'|'accent'}], ruleUsed, advice:[string], _harmony (internal) }` (โหมด idea: items = null มีแต่สี; โหมด wardrobe: items = garment จริง)
- **SavedOutfit:** `{ id, name, items, proportion, ruleUsed, createdAt }`
- **Storage:** localStorage key เดียว เก็บ { wardrobe:[Garment], favorites:[SavedOutfit], settings }

## 7. ข้อจำกัดทางเทคนิค
- self-contained, ไม่มี external fetch/รูป/สคริปต์ (ผ่าน CSP ของ artifact); libs (ถ้ามี) โหลดจาก cdnjs แบบ pin version เท่านั้น
- รูปเป็น data URL ย่อขนาด (<=2/ชิ้น) กัน localStorage เต็ม; ทุก read/write localStorage ครอบ try/catch
- ธีม light/dark (3-state), responsive, a11y: ไม่สื่อด้วยสีอย่างเดียว (มีชื่อสี/hex/ชื่อ rule/สัดส่วนกำกับ), คอนทราสต์ผ่านมาตรฐาน
- ดีไซน์: สีแบบ Rand (สีแบน คอนทราสต์ชัด) ตามพาเลตต์ในหัวข้อ 7A, เคารพ prefers-reduced-motion

## 7A. สไตล์สีและดีไซน์ (Visual style, อ้างอิงภาพตัวอย่าง)
อ้างอิงจากภาพที่ผู้ใช้ส่ง (แนว Kokonut / editorial minimal): **พื้นออฟไวท์ + ตัวอักษรดำเกือบสนิท + สีเน้นเดียวเป็นแดง raspberry สด**, สีแบนล้วน ไม่มี gradient, คอนทราสต์สูง, เว้นที่ว่างเยอะ, การ์ดรูปมุมมน, หัวข้อฟอนต์ sans หนา

### โทเคนสี (Light)
- `--bg` พื้นหน้า: `#FBFAF7` (off-white อุ่น)
- `--surface` การ์ด: `#FFFFFF`
- `--ink` ตัวอักษรหลัก: `#17161A` (ดำเกือบสนิท)
- `--ink-muted` ตัวอักษรรอง/บอดี้: `#6E6B66` (เทาอุ่น)
- `--line` เส้นคั่นบาง: `#ECE9E2`
- `--accent` สีเน้น: `#E23A4E` (แดง raspberry)
- `--accent-ink` ตัวอักษรบนสีเน้น: `#FFFFFF`
- `--accent-hover`: `#C62F41`

### โทเคนสี (Dark)
- `--bg`: `#141316` / `--surface`: `#1C1B1F`
- `--ink`: `#F4F1EA` / `--ink-muted`: `#A7A29A` / `--line`: `#2B2A2E`
- `--accent`: `#F1596B` (แดงสว่างขึ้นให้คอนทราสต์บนพื้นมืด) / `--accent-hover`: `#FF6E7E`

### ตัวอักษร (Typography)
- หัวข้อ (H1/wordmark): sans หนามาก (stack: `Inter`/`Helvetica Neue`/system-ui), ขนาดใหญ่ ระยะตัวอักษรแน่นเล็กน้อย
- บอดี้: sans ปกติ สี `--ink-muted`
- eyebrow label (เช่น "SUMMER 2025", "Innovate & Grow"): ตัวเล็ก อาจตัวพิมพ์ใหญ่/หนา ใช้สี `--accent`

### วินัยการใช้สีเน้น (สำคัญ, แบบ Rand)
- ใช้แดง `--accent` "จุดเดียวต่อบริบท": ปุ่มหลัก (CTA), eyebrow label, หรือไฮไลต์คีย์ ไม่ถมพื้นที่ใหญ่
- คงคอนทราสต์ figure/ground สูง, ไม่มี gradient/เงาฟุ้ง
- มุมโค้งการ์ด/รูป ~14-18px, ปุ่มโค้ง ~10-12px

### ข้อควรระวังเฉพาะแอปนี้ (a11y + ชนกับข้อมูล)
- **สีเน้นแบรนด์ (แดง) ต้องแยกออกจาก "สวอทช์สีเสื้อผ้าจริง" ของผู้ใช้ให้ชัด** เพราะหน้าจอโชว์สีเสื้อผ้าเป็นชิป ถ้าผู้ใช้มีเสื้อสีแดงจะสับสนกับสี CTA ได้ => วาง swatch ในกรอบ/มีป้ายกำกับ และไม่ใช้แดงแบรนด์ไปสื่อความหมายในกราฟสัดส่วนสี
- ยังคงกฎ "ไม่สื่อด้วยสีอย่างเดียว": ทุกที่ที่ใช้สีต้องมีชื่อสี/hex/ป้ายกำกับควบคู่

## 7B. UI การแสดงชุด: กรอบสี่เหลี่ยมต่อหมวด (Outfit tiles)
อ้างอิงเฟรมภาพจากคลิปที่ผู้ใช้ส่ง: แต่ละชุดอยู่ใน **การ์ดสี่เหลี่ยม** จัดเป็น **carousel** (การ์ดที่โฟกัสอยู่กลางจอ ใหญ่/ยกเด่น การ์ดข้างๆ เห็นขอบจางๆ) มีปุ่มสี่เหลี่ยม `<` `>` ด้านล่างเลื่อนดูชุดถัดไป/ก่อนหน้า และเปลี่ยนการ์ดด้วยแอนิเมชั่นแบบ **pan (เลื่อนแนวนอน)**

### การ์ดชุด (แต่ละชุด = 1 การ์ด)
- การ์ดพื้นผิว `--surface` มุมโค้ง ~16px คอนทราสต์กับพื้น (มี detail มุมตัด/dog-ear ที่มุมได้ตามคลิป เป็นลูกเล่น ไม่บังคับ)
- ภายในการ์ดจัดชิ้นเสื้อผ้าเป็น **ช่องสี่เหลี่ยมต่อหมวด** เรียง **บนลงล่างตามการแต่งจริง**: บน -> ล่าง -> รองเท้า; ถ้ามี นอก/แอกเซสต่อท้าย
  - โหมด **"สีที่ลูกค้ามี"**: ช่องโชว์ **รูปเสื้อผ้าจริง** ถ้ามี ไม่มีรูป = **บล็อกสีทึบ (hex ของชิ้น)**
  - โหมด **"สีที่เราแนะนำ"**: ช่องเป็น **บล็อกสีทึบ** ของสีที่แนะนำ (ไม่มีของจริง)
  - ทุกช่องมีป้าย: ชื่อหมวด + ชื่อสี/hex (คุม a11y)
- ใต้ช่องในการ์ด: แถบ **สัดส่วนสี 60-30-10 + % รายสี** และ **คำแนะนำ** ของชุดนั้น (ตาม 4.4-4.5)

### Carousel + การเลื่อน (จากคลิป)
- แต่ละครั้งโชว์ **แบตช์ละ 3-4 ชุด** วางเป็น **carousel แนวนอน**: การ์ดที่โฟกัสอยู่กลาง **ใหญ่/ยกเด่น (เงา)**; การ์ดก่อนหน้า/ถัดไปเห็นขอบจางๆ ทั้งสองข้าง (จาง + ย่อเล็กน้อย)
- **ปุ่มสี่เหลี่ยม `<` `>` ใต้การ์ด** เลื่อนก่อนหน้า/ถัดไป **แบบวนลูปภายในแบตช์** (ถึงใบสุดท้ายกด "ถัดไป" วนกลับใบแรก; ใบแรกกด "ก่อนหน้า" ไปใบสุดท้าย); รองรับ **ปัดซ้าย-ขวา (swipe)** ด้วย
- เปลี่ยนการ์ดด้วยแอนิเมชั่น **pan (translateX ลื่นไหล)** ~250-350ms ease; **prefers-reduced-motion = ตัด pan เหลือสลับทันที/เฟดจางๆ**
- ตัวบอกตำแหน่ง (เช่น 2/4 หรือจุด dots) ให้รู้ว่าอยู่ชุดที่เท่าไรในแบตช์
- **ปุ่มแยก "เจนชุดใหม่ (✨ Generate)"** = สร้างแบตช์ใหม่ 3-4 ชุดมาแทนของเดิม (การเลื่อน `<` `>` ไม่สร้างชุดใหม่เอง จะวนลูปในแบตช์เดิมจนกว่าผู้ใช้กด Generate)

### การแก้ทีละชิ้น (ผูก FR-2, เฟส 2)
- แตะช่องหมวดใดในการ์ดที่โฟกัส = เปลี่ยนเฉพาะหมวดนั้น (Swap One Item) ชิ้นอื่นคงเดิม; ช่องเสริมที่ว่าง = เส้นประ "+ เพิ่ม/ไม่มี"

### Acceptance (ผูกกับ FR-1/FR-2)
- ชุดแสดงเป็นการ์ด, ในการ์ดมีช่องสี่เหลี่ยมต่อหมวด เรียงบน->ล่าง->รองเท้า
- มีปุ่ม `<` `>` (และ swipe) เลื่อนชุด; เปลี่ยนการ์ดมี pan animation; ปิด pan เมื่อ reduced-motion
- โฟกัสการ์ดกลางเด่น การ์ดข้างจาง; มีตัวบอกตำแหน่งชุด
- โชว์รูปจริงถ้ามี ไม่มีรูปเป็นบล็อกสี + ป้ายชื่อสี/หมวดทุกช่อง

## 7C. UI States & Edge Cases
แต่ละสถานะต้องมีหน้าตา/ข้อความชัด ไม่ปล่อยให้หน้าค้างหรือแนะนำมั่ว

### สถานะจากที่ผู้ใช้ระบุ
- **First load (ค่าเริ่มต้น):** เปิดเว็บมามีชุดตัวอย่าง (seed) ให้เห็นผลทันที + ป้าย "ตัวอย่าง"
- **Empty:** ยังไม่มีเสื้อผ้าจริง (หลังผู้ใช้ล้างตัวอย่าง) => โหมด "สีที่ลูกค้ามี" ว่าง ชวนเพิ่มชิ้นแรก; โหมด "สีที่เราแนะนำ" ยังใช้ได้
- **Loading:** กำลังประมวลผลรูป/ดึงสี => โชว์ตัว spinner/skeleton บนช่องนั้น กันกดซ้ำ
- **Insufficient Data:** มีบนแต่ไม่มีล่าง (หรือกลับกัน) => โหมด wardrobe แสดง "ขาด [หมวด] เพิ่มอีกนิดเพื่อจัดชุด" + ปุ่มเพิ่ม; ยังสลับไปโหมด "สีที่เราแนะนำ" ได้
- **No Match:** มีของครบหมวดแต่จับตาม constraint ไม่ได้ (เช่น color-first ล็อกสีที่ไม่มีคู่เข้ากัน) => "ยังหาคู่ที่เข้ากับ [สี/เงื่อนไข] ไม่ได้" + เสนอผ่อนเงื่อนไข (เช่น เอา neutral มาคุม) หรือสลับโหมดไอเดีย
- **Storage Error (บันทึกไม่ได้):** localStorage ถูกบล็อก (โหมดส่วนตัว) => แบนเนอร์ "ใช้งานได้ แต่จะไม่บันทึกถาวรในเครื่องนี้" ทุกอย่างทำงานในหน่วยความจำชั่วคราว
- **Image Error:** อ่านไฟล์รูปไม่ได้/ไม่ใช่รูป => ข้อความ "อ่านรูปไม่สำเร็จ ลองไฟล์อื่น" คงช่องสีให้กรอก hex เองได้
- **Deleted Garment:** Favorite อ้างถึง garment ที่ถูกลบ => (ยืนยันแล้ว) เก็บ snapshot สี+ชื่อตอน Save ทำให้ favorite ยังโชว์สีได้เสมอ; ถ้ากดแก้จะเตือนว่าชิ้นเดิมถูกลบแล้ว

### เคสที่ผมเห็นว่าขาด (เพิ่มให้)
- **Single item in category:** หมวดนั้นมีชิ้นเดียว => ปุ่ม Swap หมวดนั้น disabled + hint "มีชิ้นเดียวในหมวดนี้"
- **All-neutral / no-accent wardrobe:** ตู้มีแต่สีกลาง => ยังจัดชุดได้ (โทน monochrome/neutral) แต่ Analysis ชวนเพิ่ม accent; ไม่แสร้งว่ามีสีเด่น
- **Storage quota exceeded:** เซฟรูปแล้ว localStorage เต็ม => (ยืนยันแล้ว) เตือนแล้วเซฟชิ้นนั้นแบบไม่มีรูป (ข้อมูลสี/หมวดยังอยู่) + แนะให้ลบรูปเก่า
- **Large wardrobe (combinatorial):** ของเยอะจน combination บานปลาย => จำกัดการค้นหา/สุ่มตัวอย่าง combination (cap) เพื่อไม่ให้หน้าค้าง ยังได้แบตช์ 3-4 ชุดเร็ว
- **Color extraction ambiguous:** ดึงสีจากรูปแล้วได้สีเพี้ยน (พื้นหลังเด่น) => ถือเป็นเรื่องปกติ ผู้ใช้แก้ hex ได้ทันที (สอดคล้อง 4.x "รูปเป็นตัวช่วย ไม่ใช่ตัวตัดสิน")
- **Reduced motion:** ผู้ใช้เปิด prefers-reduced-motion => ตัด pan/แอนิเมชั่นทั้งหมด เหลือสลับทันที (อ้าง 7B)
- **Shared link / เครื่องใหม่:** เปิดลิงก์บนเครื่องที่ localStorage ว่าง => เห็นชุดตัวอย่าง (ไม่เห็นตู้ของเครื่องอื่น เพราะข้อมูลอยู่ในเครื่อง)
- **Favorites เต็ม (20 ชุด):** กด Save เกิน 20 => เตือน "บันทึกครบ 20 ชุดแล้ว ลบชุดเก่าก่อนเพื่อเซฟใหม่" ไม่เงียบๆ ดรอป

## 8. แผนเฟส (ส่งมอบทีละเฟส แต่ละเฟสใช้งานได้จริง)
- **เฟส 1 (ขอบเขตรอบแรก):** FR-0 Wardrobe + Color Matching Engine (4.1-4.6, รวมสองโหมดผลลัพธ์) + FR-1 Today Outfit พร้อมตัวสลับ "สีที่เราแนะนำ" / "สีที่ลูกค้ามี" + seed ตัวอย่าง + ดีไซน์ฐานตามพาเลตต์หัวข้อ 7A + light/dark + a11y
- **เฟส 2:** FR-2 Swap + FR-3 Favorites
- **เฟส 3:** FR-4 Analysis + FR-5 Color-first + FR-6 Generator

## 9. สมมติฐาน/ค่าตั้งต้น (ปรับได้ตอนสร้าง)
- threshold neutral S < 20%; ช่วงองศาของแต่ละ rule ตาม 4.2 (จูนจากผลจริง)
- โชว์แบตช์ละ 3-4 ชุด (ปุ่ม </> วนลูปในแบตช์, ปุ่ม "เจนชุดใหม่" สร้างแบตช์ใหม่); รูปสูงสุด 2/ชิ้น
- 5 harmony rules ตามที่ระบุ
- หมวดเริ่มต้น 5 หมวด
- **Favorite สูงสุด 20 ชุด** (เก็บ snapshot สี+ชื่อ ไม่เก็บรูปในตัว favorite); ครบแล้วให้เตือนลบชุดเก่าก่อนเซฟใหม่

## 10. แผนตรวจสอบ (verification)
- เปิดเว็บครั้งแรก (ยังไม่มีข้อมูล) เห็นชุดตัวอย่างแนะนำได้ทันที
- เพิ่มเสื้อผ้าจริงจากรูป -> ดึงสีได้ + แก้ hex ได้ -> Today Outfit ใช้ของจริง
- ตรวจ AC ของแต่ละ FR ในเฟสนั้นด้วยการลองจริงในหน้า (ไม่ใช่สันนิษฐาน)
- รีเฟรชแล้วข้อมูลอยู่; ล้าง localStorage แล้วกลับไปสถานะตัวอย่าง
- ตรวจ light/dark + คอนทราสต์ + ไม่มี external request หลุด CSP

## 11. แผนสำรอง (Backlog / ยังไม่ทำ)
ไอเดียใช้พื้นที่/งบ localStorage ที่เหลือให้คุ้ม เก็บไว้พิจารณาหลังแกนเสร็จ (ไม่อยู่ในเฟส 1-3):
1. **Thumbnail ต่อ favorite**: เก็บภาพย่อเล็กต่อชุดที่เซฟ (20 ชุด ~300KB) ให้หน้า Favorites จำง่าย/สวยขึ้น
2. **แท็ก/โน้ตต่อชิ้น (โอกาส/ฤดู/ตัวโปรด)**: ข้อความเบามาก ช่วยให้ Occasion แม่นขึ้นจริง (แก้จุดอ่อนที่ engine ไม่รู้ความเป็นทางการของเสื้อผ้า)
3. **ประวัติการใส่ (worn log)**: กด "ใส่ชุดนี้วันนี้" เก็บวันที่ ต่อยอดเป็นปฏิทิน/สถิติชุดที่ใส่บ่อย
4. **ถังขยะ/undo ลบ garment**: เก็บชิ้นที่เพิ่งลบไว้กู้คืน กันลบพลาด
5. **รูปคมขึ้น / เพิ่มเป็น 3-4 รูปต่อชิ้น**: ต้องมีตัวนับพื้นที่กันชนเพดาน

รวมของเดิม: ฤดู/สภาพอากาศ, จำกัดโทนตามสภาพผิว, แชร์ชุดให้คนอื่น, รองรับลายผ้า, quantize หลายสีตอนดึงสีจากรูป, เรียก AI ช่วยเขียนคำแนะนำสด
