# สรุปผลการ Grill: Outfit Color Matcher (ปรับสเปกหลังซักถาม)

> เอกสารนี้คือ "ข้อสรุปการตัดสินใจ" จากการ grill สเปก v1 ยังไม่ลงมือสร้าง
> ใช้คู่กับไฟล์สเปกเดิม (`outfit-color-matcher.md`) โดยข้อสรุปด้านล่างถือเป็นตัวตัดสินเมื่อขัดกับ v1

## จุดเปลี่ยนใหญ่ที่สุด: ปรัชญาผลิตภัณฑ์
**เว็บนี้จะไม่ "ให้คะแนน" หรือ "ตัดสิน/วิจารณ์" การแต่งตัว**
แทนที่ด้วย: **คำแนะนำอิงทฤษฎีสี + ตัวเลขบอกสัดส่วนสีของลุค**
- ผลที่ตามมา: ตัด "Match Score 96/91/89" และภาษาแบบจัดอันดับความดี-ด้อยออกจากสเปก v1 ทั้งหมด
- แต่ระบบยัง "เลือกและเรียง" ชุดที่จะโชว์ได้ โดย **คำนวณความกลมกลืนเงียบๆ เบื้องหลัง** (ไม่แสดงเป็นเกรดให้ผู้ใช้เห็น)

## การตัดสินใจที่ได้ข้อสรุป (12 ข้อ)

1. **การเลือก Top 3:** คำนวณเงียบเบื้องหลังเพื่อคัด/เรียงชุดที่กลมกลืน ไม่โชว์ตัวเลขความกลมกลืนออกมาเป็นคะแนน
2. **ตัวเลขพระเอก (แทน Match Score):** สัดส่วนสีของลุคแบบ **60-30-10** (หลัก/รอง/เน้น) **บวกกับ % รายสี** (เช่น Navy 55 / Cream 30 / White 15)
3. **วิธีรู้ว่าสีไหน 60/30/10:** กำหนด **ตามหมวดเสื้อผ้า** (บน+ล่าง = สัดส่วนหลัก, นอก = รอง, รองเท้า/แอกเซสซอรี = เน้น) แล้วรวมสีตามน้ำหนักหมวด
4. **นิยาม neutral vs accent:** คำนวณอัตโนมัติ **จากค่า HSL** (อิ่มสีต่ำ = neutral: ขาว/ดำ/เทา/เบจ/กรมเข้มมาก, นอกนั้นแยก warm/cool ตามเฉด)
5. **โอกาส (Occasion):** มีผลกับ **การปรับโทนสีเท่านั้น** (Work/Dinner เอนโทนเข้ม/สีกลาง, Party ยอม accent จัดขึ้น, Everyday/Cafe โทนสบายกลางๆ) ไม่แสร้งรู้ความเป็นทางการของเสื้อผ้าจริง
6. **Cold-start (ตู้ว่าง):** ใส่เสื้อผ้า **ตัวอย่างติดป้าย "ตัวอย่าง"** ให้แนะนำได้ตั้งแต่เปิดเว็บ + ปุ่มล้างตัวอย่าง; ถ้าหมวดจำเป็นขาด ให้ **ชวนเพิ่มชิ้นที่ขาด** ไม่แนะนำมั่ว
7. **ชุดที่นับว่าครบ:** ต้องมี **บน + ล่าง** เป็นอย่างน้อย; นอก/รองเท้า/แอกเซสซอรี = เสริม (ใส่ถ้ามีในตู้)
8. **ดึงสีจากรูป:** ทำแบบ **พอใช้ + ผู้ใช้แก้ค่า hex เองได้เสมอ** (เฉลี่ยสีโซนกลางภาพ เลี่ยงพื้นหลัง) ถือว่ารูปเป็นตัวช่วย ไม่ใช่ตัวตัดสิน
9. **คำแนะนำอิงทฤษฎีสี:** ใช้ **ข้อความสำเร็จรูป (template)** เลือกตามความสัมพันธ์ของสีที่ตรวจเจอ (analogous/complementary/triadic/monochrome/neutral+accent) + สัดส่วน คุมโทนได้ ไม่หลอน
10. **Swap One Item:** ล็อกชิ้นอื่นไว้ **สลับทีละชิ้น วนได้** (กดซ้ำเพื่อวนตัวถัดไปที่เข้ากันดีในหมวดนั้น)
11. **Mode B (โทนสีไอเดีย / Outfit Generator ไม่ต้องมีของจริง):** **สร้าง palette จากกฎสีสดๆ** (สุ่มสีตั้งต้นตาม Color filter แล้วดึงสีตาม rule + จัดสัดส่วน 60-30-10)
12. **จำนวนผล + Generate:** โชว์ **เท่าที่จับคู่ได้ (สูงสุด 3)**; กด Generate = **หมุนไปชุดถัดไป** ที่เข้ากัน; ตู้เล็กจับได้ไม่ถึง 3 ก็โชว์เท่าที่มี

### Wardrobe Color Analysis (จุดต่างของเว็บ)
- **insight + "สีที่ช่วยเพิ่มการจับคู่":** สร้างจาก **กฎ threshold + template** เช่น neutral > 70% → "ตู้คุณโทนสงบมาก ลองเพิ่ม accent 1 สีเพื่อเพิ่มลุค"
- **สีที่แนะนำ** = สีที่เข้ากับสีฐานที่มีมากสุดในตู้ (ตามกฎสี) แต่ยังขาดในตู้; เขียนเชิง "เพิ่มตัวเลือกการจับคู่" **ไม่ใช่บอกให้ไปซื้อ**
- ถ้าข้อมูลน้อยเกินไปให้บอกผู้ใช้ตรงๆ แทนการวิเคราะห์มั่ว

## ค่าตั้งต้นที่ผมกำหนดเอง (ปรับได้ตอนสร้าง)
- Threshold neutral: อิ่มสี (S) ต่ำกว่า ~15-20% ใน HSL = neutral (จะจูนจากผลจริง)
- ชุด harmony rules = 5 แบบตาม v1
- รูปต่อชิ้น สูงสุด 2 รูป, เก็บเป็น data URL ย่อขนาด, ทั้งหมดใน localStorage
- ไม่ใช้ capability ใดๆ (เพื่อแชร์สาธารณะได้) → ตัดตัวเลือก "เรียก AI ตอบสด" ออก ใช้ template ล้วน

## สิ่งที่ไม่เปลี่ยนจาก v1
- เว็บหน้าเดียว self-contained, localStorage, light/dark, responsive, a11y (ไม่สื่อด้วยสีอย่างเดียว: โชว์ชื่อสี/hex/ชื่อ rule/สัดส่วนกำกับ)
- เสื้อผ้าสีเดียว ไม่มีลาย
- Color Matching Engine เป็นแกนกลางเดียวที่ทุกฟีเจอร์ใช้ร่วม
- แผนแบ่ง 3 เฟส (เฟส 1: Wardrobe + Today Outfit; เฟส 2: Swap + Favorites; เฟส 3: Color-first + Generator + Analysis)
