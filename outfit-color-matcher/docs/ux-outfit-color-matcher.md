# UX Design: Outfit Color Matcher

> ออกแบบประสบการณ์ผู้ใช้ก่อนลงรายละเอียด UI จากสเปกฉบับสมบูรณ์ (sections 1-11)
> เว็บหน้าเดียว (single-page) จึง "screen" = view/section ในหน้าเดียวกัน สลับด้วย state ไม่ใช่เปลี่ยนหน้า
> ทำเครื่องหมาย [P1]/[P2]/[P3]/[P4-A..D] ตามเฟส (P4 = System Overhaul, ดู `.scratch/outfit-color-matcher/spec.md`)

## 0. Target user & wording (ตัดสินแล้ว)
- **Target = ใครก็ได้** เว็บสาธารณะที่ **ปัจเจกแต่ละคนเปิดมาใช้แต่งตัวให้ตัวเอง** (ไม่ใช่สไตลิสต์/ร้านแต่งให้ลูกค้าหลายคน)
- **ผลต่อ IA:** ตู้เดียวต่อเครื่อง (localStorage) ไม่มีหลายโปรไฟล์/หลายตู้
- **ผลต่อ label:** ใช้มุมมอง **บุรุษที่ 1** ("ของฉัน") ที่ใครเปิดก็อ่านเป็นของตัวเอง; **เลิกใช้คำว่า "ลูกค้า"** ทุกที่
  - โหมด: `สีที่เราแนะนำ` (แอปเสนอไอเดีย) / `จากตู้ของฉัน` (จากเสื้อผ้าจริงของผู้ใช้เอง)

## 1. เป้าหมายผู้ใช้ (User goals)
- G1: ได้ไอเดียชุดที่สีเข้ากัน "ทันที" โดยไม่ต้องคิดเอง (พระเอก)
- G2: ใช้เสื้อผ้าที่มีจริงในตู้ให้เกิดประโยชน์ (แมทจากของจริง)
- G3: ลองเล่นสี/หาแรงบันดาลใจ แม้ยังไม่มีเสื้อผ้าในระบบ
- G4: เก็บชุดที่ชอบไว้ใช้ซ้ำ
- G5: เข้าใจ "ตู้ตัวเอง" ว่ามีโทนสีแบบไหน (สำรวจ)
- **G6 [P4-B]:** ปรับชุดที่แนะนำทีละชิ้นจนกว่าจะถูกใจ โดยรู้ว่าตัวไหนน่าจะเข้ากันดีที่สุด (ไม่ใช่วนสุ่มเดา)
- **G7 [P4-A]:** ได้คำแนะนำที่มีประโยชน์แม้ตู้ยังมีของไม่ครบ/เอียงไปทางหมวดใดหมวดหนึ่ง
- **G8 [P4-C]:** รู้สึกว่าเว็บมีเอกลักษณ์ ไม่ใช่หน้าตาทั่วไป และธีมมีชีวิตชีวาตามชุดที่กำลังดู
- **G9 [P4-D]:** หาสีที่ต้องการเจอเร็ว แม้ตู้มีของเยอะหรือกำลังเลือกสีให้ชิ้นใหม่ที่ยังไม่มีของ

## 2. User Journey (end-to-end)
```
รู้จัก/เปิดลิงก์ → เห็นคุณค่าทันที (ชุดตัวอย่าง) → ลองกด "วันนี้แต่งอะไรดี?"
   → [อยากได้ของจริง] เพิ่มเสื้อผ้า (เลือกทรง + เลือกสี) → แมทจากตู้
   → เจอชุดที่ชอบ → Favorite / Swap ปรับ / เจนใหม่
   → กลับมาใช้ซ้ำ (ตู้+favorite ยังอยู่ในเครื่อง)
```
หลักการ: **เห็นคุณค่าก่อนลงแรง** (value before setup) ผู้ใช้ไม่ต้องกรอกตู้ก่อนถึงจะได้ผล

## 3. Information Architecture (โครงหน้าเดียว)
ลำดับ section บนหน้า (เลื่อน/จัมป์ได้):
```
[Header] ชื่อเว็บ + ปุ่มหลัก "วันนี้แต่งอะไรดี?" + ปุ่มล็อกธีม [P4-C, global]
   │
[1] แผงแนะนำชุด (Results)  ← หัวใจ อยู่บนสุด เห็นก่อน
     - ตัวสลับโหมด: [สีที่เราแนะนำ] [จากตู้ของฉัน]
     - แถบเลือก Occasion + แถว "วันนี้อยากใส่สีอะไร?" (มีปุ่ม "ดูสีเพิ่มเติม" ต่อท้าย) [P4-D]
     - Carousel การ์ดชุด + ปุ่ม < > + ปุ่ม "เจนชุดใหม่"
   │
[2] ตู้เสื้อผ้า (Wardrobe)  ← รอง เลื่อนลงเจอ
     - ปุ่ม + เพิ่มชิ้น / กริดชิปสี / แก้-ลบ
     - ฟอร์มเพิ่ม/แก้ไข: ตัวเลือกสีมีปุ่ม "ดูสีเพิ่มเติม" ต่อท้ายเช่นกัน [P4-D]
   │
[3] Favorites [P2]  ← ชุดที่บันทึก
   │
[4] วิเคราะห์ตู้ (Analysis) [P3]
```
**การนำทาง:** แถบเมนู sticky บนสุด (แนะนำ / ตู้ / บันทึก / วิเคราะห์) จัมป์ไป section; บนมือถือย่อเป็นแท็บล่างหรือปุ่มจัมป์

**ชั้นซ้อนทับ (overlay layer) ใหม่ [P4-D]:** มุมมองจัดกลุ่มตามโทนสี ("View More Colors") ไม่ใช่ section ใหม่ในลำดับข้างบน แต่เป็น modal ที่เปิดจากสองจุด (แถวสีในการ์ดแนะนำ, ฟอร์มเพิ่ม/แก้ไขชิ้นเสื้อผ้า) แล้วปิดกลับไปจุดเดิมเสมอ ไม่เปลี่ยน IA หลัก

**ปุ่มล็อกธีม [P4-C]:** อยู่ที่ระดับ Header (ผลกับพื้นหลังทั้งหน้า ไม่ใช่ของ section ใดโดยเฉพาะ) ต้องแยกตำแหน่ง/ไอคอนให้ชัดจากสวอตช์ "ล็อกสี" ใน section [1] เพราะเป็นคนละแนวคิดกัน (ดู §7 ข้อควบคุมการตั้งชื่อ/ไอคอน)

## 4. Screen/State Map (สำหรับ ui-design)
> แต่ละ "view" คือสถานะของ section เดียวกัน

### View A: Results (แผงแนะนำ) [P1]
- A0 First-load: โชว์ผลจากชุดตัวอย่างทันที (โหมด default ตามความพร้อมตู้)
- A1 Idea mode ("สีที่เราแนะนำ"): carousel การ์ด = สวอทช์สีต่อหมวด + สัดส่วน + คำแนะนำ
- A2 Wardrobe mode ("จากตู้ของฉัน"): carousel การ์ด = ชิ้นจริง/บล็อกสี + สัดส่วน + คำแนะนำ
- **A3 Insufficient [แก้ไข P4-A]:** เกณฑ์เปลี่ยนจาก "ขาดบน/ล่าง" เป็น "ตู้มีของรวมน้อยกว่า 2 ชิ้น" ข้อความทั่วไปว่า "เพิ่มอีกอย่างน้อย 1 ชิ้นเพื่อเริ่มจับคู่" (ไม่เอ่ยชื่อหมวดเฉพาะอีกต่อไป เพราะไม่มีหมวดที่ถูกบังคับแล้ว) + ปุ่มเพิ่ม + ชี้ให้ลองโหมดไอเดีย
- A4 No-match (เกิดจริงเมื่อล็อกสีใน FR-5): บอกว่าล็อกสีอะไรและตู้ไม่มีชิ้นสีนั้นเลยสักชิ้น (นิยาม "ชิ้นหลัก" ขยายเป็นหมวดใดก็ได้แล้ว ดู AF1 ที่แก้ตาม) + ปุ่ม "เอาสีที่ล็อกออก" / สลับไปโหมดไอเดีย
- A5 Generating/transition: pan animation ระหว่างการ์ด (skip เมื่อ reduced-motion); **[เพิ่ม P4-C]** พื้นหลังหน้าเปลี่ยนโทนตามสีหลักของชุดที่โฟกัสในแบตช์ใหม่พร้อมกัน ใช้แอนิเมชั่นเดียวกับกฎ reduced-motion (ปกติ = ไล่สี, reduced = สลับทันที) เว้นแต่ธีมถูกล็อกไว้
- **A6 [P4-B] Card ที่ไม่มีบางหมวด:** การ์ดที่มีของแค่บางหมวด (เช่นเสื้อนอก+รองเท้า) ไม่เหลือช่องว่างของหมวดที่ขาด เลย์เอาต์ยุบพื้นที่นั้นทิ้ง ไม่ใช่โชว์ช่องว่างเปล่า

### View B: Wardrobe (ตู้) [P1]
- B0 Empty (จริงๆ): ชวนเพิ่มชิ้นแรก
- B1 มีของ: กริดชิปสี (ชื่อ+หมวด+ชื่อสี)
- B2 Add/Edit form: **หมวด → ทรง (ShapePicker) → สี (พรีเซ็ต/color/hex) → ชื่อ (ไม่บังคับ)** พร้อมพรีวิวสด; **[เพิ่ม P4-D]** ตัวเลือกสีมีปุ่ม "ดูสีเพิ่มเติม" เปิด modal จัดกลุ่มตามโทนจาก `PRESET_COLORS` **ทั้งชุด** (ไม่กรองเฉพาะของที่มีในตู้ เพราะจุดนี้ใช้ตอนตู้ยังว่างพอดี)
- B3 Storage error: ข้อความตาม 7C (ไม่มีสถานะ loading/image-error แล้ว เพราะไม่มีการอ่านไฟล์รูป)
- B4 Unknown shape: `shapeId` ไม่รู้จัก → วาดทรงเริ่มต้นของหมวดแทน + หมายเหตุ
- **B5 [P4-D] Garment tile ใหม่:** ใช้ระบบภาพ Collage Art Style เดียวกับการ์ดแนะนำ (ดู `.scratch/outfit-color-matcher/spec.md` Decision #3/#5) ทุกหมวดเหมือนกัน

### View C: Outfit Detail / actions [P1-P2, P4-B]
- การ์ดที่โฟกัส: ช่องหมวด (บน→ล่าง→รองเท้า) + แถบสัดส่วน 60-30-10 + คำแนะนำ; **[P4-B]** ช่องที่ไม่มีชิ้นในหมวดนั้นไม่แสดงเลย (A6)
- ปุ่มการ์ด: ❤️ Favorite [P2] · 🔄 Swap ทีละชิ้น [P2] · (เลื่อน < >)
- **[แก้ไข P4-B] Swap ใช้ได้ทุกการ์ดในแบตช์แล้ว** ไม่จำกัดแค่การ์ดโฟกัส กดที่การ์ดข้างๆ ได้เลยโดยไม่ต้องเลื่อนมาโฟกัสก่อน
- **[เพิ่ม P4-B] ปุ่ม Swap มี 3 สถานะย่อย:** ปกติ (วนตัวถัดไปตามคะแนน, ตัวที่คะแนนดีที่สุดมีป้าย "แนะนำ" ตอนวนมาเจอ) · disabled เพราะมีชิ้นเดียวในหมวด (เดิม) · disabled เพราะหมวดนั้นเป็นหมวดเดียวที่ถือ "สีที่ล็อกไว้วันนี้" อยู่ (ใหม่ ข้อความต่างจากกรณีชิ้นเดียว ดู §7B)
- **[เพิ่ม P4-B] ตัวชี้ล็อกสีบนปุ่ม Swap:** หมวดที่ถูกป้องกันเพราะถือสีล็อกอยู่ (ไม่ว่าจะกดจนหมดตัวเลือกหรือยัง) มีไอคอนเล็กๆ กำกับตลอดเวลา ไม่ใช่โผล่ตอนกดแล้วโดนบล็อกเท่านั้น (progressive disclosure: เห็นเหตุผลได้ก่อนลองกด)

### View D: Favorites [P2]
- D0 ว่าง: "ยังไม่มีชุดที่บันทึก" · D1 มีรายการ (การ์ด + rename/delete/duplicate) · D2 เต็ม 20

### View E: Analysis [P3]
- E0 ข้อมูลน้อยเกินไป: บอกตรงๆ · E1 มีผล: สัดส่วนสี + กลุ่ม + insight + สีที่ช่วยเพิ่มการจับคู่

## 5. Primary Flow (พระเอก: วันนี้แต่งอะไรดี) [P1]
```
กด "วันนี้แต่งอะไรดี?"
 → เลือก Occasion (default = ไม่ระบุ, เลือกได้ทันที)
 → เลือกโหมด (default อัตโนมัติตามตู้: ตู้พอ=จากตู้ของฉัน, ไม่พอ=สีที่เราแนะนำ)
 → เห็นแบตช์ 3-4 ชุด (การ์ดแรกโฟกัส)
 → เลื่อน < > / swipe ดูภายในแบตช์ (วนลูป)
 → พอใจ: Favorite / อยากปรับ: Swap / เบื่อ: เจนชุดใหม่
```
**Feedback ที่ต้องมี:** เปลี่ยน Occasion/โหมด → แบตช์อัปเดตพร้อม transition; เจนใหม่ → การ์ดชุดเปลี่ยนชัด; ทุกการ์ดมีสัดส่วน+คำแนะนำเสมอ; **[เพิ่ม P4-C]** เจนใหม่ → พื้นหลังหน้าเปลี่ยนโทนตามชุดใหม่ด้วย (เว้นแต่ล็อกธีมไว้)

**[แก้ไข P4-A] "ชุดครบ" ไม่ใช่บน+ล่างอีกต่อไป:** โหมด "จากตู้ของฉัน" แนะนำชุดได้แม้มีของแค่ 2 หมวดขึ้นไปจากหมวดไหนก็ได้ (เดิมบังคับต้องมีบน+ล่าง) ผลคือ Insufficient (A3) เกิดยากขึ้นมาก (แค่ตู้มีของรวมน้อยกว่า 2 ชิ้นเท่านั้น) และผู้ใช้ที่มีของกระจุกในบางหมวด (เช่นมีแต่เสื้อนอกกับรองเท้า) เริ่มได้คำแนะนำตั้งแต่ต้น ไม่ต้องรอเพิ่มครบตามโครงสร้างเดิม

## 6. Alternative Flows
- **AF1 นำสีเอง (color-first) [P3, ทำแล้ว; นิยามแก้ไข P4-A]:** เลือกสีจากแถว "วันนี้อยากใส่สีอะไร?" (สวอตช์ = สีจริงในตู้ก่อน แล้วต่อด้วยพรีเซ็ต, ปุ่ม "ดูสีเพิ่มเติม" [P4-D] เปิดมุมมองจัดกลุ่มตามโทนถ้าแถวยาวเกิน) → ล็อกเป็นชิ้นหลัก → ได้ชุดรอบสีนั้น
  - **"ชิ้นหลัก" ไม่ใช่แค่บนหรือล่างอีกต่อไป [แก้ไข P4-A]:** เดิมผูกกับกฎ "ชุดครบ = บน+ล่าง" ที่ตอนนี้ถูกยกเลิกแล้ว (ดู Primary Flow) นิยามใหม่คือสีที่ล็อกต้องอยู่บน**หมวดใดก็ได้อย่างน้อยหนึ่งหมวด**ในชุด ไม่จำกัดว่าต้องเป็นบน/ล่าง
  - โหมดตู้: ถ้าไม่มีชิ้น**สีนั้นเลยสักหมวดเดียว** -> A4 No-match พร้อมปุ่มเอาสีที่ล็อกออก (เกิดยากขึ้นกว่าเดิม เพราะตอนนี้แค่มีชิ้นสีนั้นอยู่ที่ไหนก็พอ ไม่ต้องเป็นบน/ล่างเท่านั้น) · โหมดไอเดีย: ล็อกได้เสมอ สีที่ล็อกกลายเป็น Primary
  - สีที่ล็อกถูกจำไว้ใน settings เหมือน occasion และทุกครั้งที่ล็อก/ปลดล็อกต้องมีข้อความกำกับ (§7B)
  - **[เพิ่ม P4-B] ผลต่อ Swap:** ถ้าล็อกสีไว้ และหมวดที่ถือสีนั้นเป็นหมวดเดียวในชุด การ Swap หมวดนั้นจะถูกจำกัดให้เลือกได้แต่ตัวเลือกสีเดียวกัน (ดู View C) กันไม่ให้กด Swap แล้วชุดหลุดจากเงื่อนไขที่ล็อกไว้แบบไม่รู้ตัว
- **AF2 หา inspiration (Generator) [P3, ปิดแล้วโดยไม่มีโค้ดใหม่]:** ปิดสโคปตามที่ผู้ใช้ตัดสินใจไว้ในเฟส 3 (ดู main spec FR-6) **ไม่เกี่ยวกับ** Decision #2 ของเฟส 4 (Flexible Outfit Generation) ซึ่งเป็นการยกเลิกกฎบน+ล่างของ engine เอง คนละเรื่องกัน อย่าสับสน
- **AF3 เริ่มจากตู้ก่อน:** เพิ่มเสื้อผ้า → แล้วค่อยกดแนะนำ (คนที่อยากเซ็ตอัปก่อน)
- **AF4 ผู้ใช้ข้ามตู้:** ใช้โหมดไอเดียกับตัวอย่างล้วน (ไม่แตะตู้เลย)
- **AF5 [P4-D] ค้นหาสีผ่านมุมมองจัดกลุ่มตามโทน:** กด "ดูสีเพิ่มเติม" (จากแถวสีของวันนี้ หรือจากฟอร์มเพิ่ม/แก้ไขชิ้นเสื้อผ้า) → เห็นรายการกลุ่มโทนสี (เช่น น้ำตาล, เทา, แดง) → แตะกลุ่ม → เห็นเฉดที่มีอยู่จริงในกลุ่มนั้น (แถวสีของวันนี้ = เฉพาะของในตู้; ฟอร์มเพิ่ม/แก้ไข = พรีเซ็ตทั้งชุด ไม่กรอง) → เลือกเฉด → modal ปิด กลับไปจุดเดิมพร้อมค่าที่เลือกไว้แล้ว + ข้อความยืนยันสั้นๆ (§7B)
- **AF6 [P4-C] ล็อกธีมพื้นหลัง:** กดปุ่มล็อกธีมที่ Header → พื้นหลังหยุดเปลี่ยนตามชุดที่เจนใหม่ (สีชุด/สัดส่วน/คำแนะนำยังทำงานปกติ) → กดอีกครั้งเพื่อปลดล็อก → กลับไปขยับตามชุดใหม่ทุกครั้งที่เจน

## 7. Interaction rules
- **โหมดเป็น 2-way toggle ค้างไว้:** จำค่าที่เลือกล่าสุด (localStorage) ไม่รีเซ็ตทุกครั้ง
- **Occasion เลือกแล้วมีผลทันที** (ไม่ต้องกดยืนยันซ้ำ)
- **< > วนลูปในแบตช์เท่านั้น**; สร้างชุดใหม่ต้องกด "เจนชุดใหม่" (แยกชัด กันสับสน)
- **Swap = กดปุ่ม 🔄 (SwapButton, .tile__swap) ท้ายไทล์ในการ์ด** เปลี่ยนเฉพาะหมวดนั้น วนตัวถัดไป [P2]; **[แก้ไข P4-B]** ใช้ได้ทุกการ์ดในแบตช์แล้ว ไม่ใช่แค่การ์ดโฟกัส
- **[เพิ่ม P4-B] Swap คำนึงถึงสีที่ล็อกไว้เสมอ:** จะไม่มีทางกด Swap แล้วชุดหลุดจากเงื่อนไข "มีสีที่ล็อก" แบบไม่รู้ตัว (ตัดตัวเลือกที่ไม่ใช่สีล็อกออกจากวง ถ้าหมวดนั้นเป็นหมวดเดียวที่ถือสีนั้นอยู่)
- **Favorite = toggle** กดซ้ำเอาออก; เต็ม 20 เตือนก่อน [P2]
- **เปลี่ยนทรงกับเปลี่ยนสีทำแยกกันได้** ไม่ต้องกรอกใหม่ทั้งชิ้น (ผู้ใช้คือผู้ตัดสินสุดท้าย)
- ทุก action ที่ลบ/แทนที่ (ลบชิ้น, เปลี่ยนทรง) มี confirm หรือ undo ที่เข้าใจได้
- **[เพิ่ม P4-C] "ล็อกสี" (FR-5) กับ "ล็อกธีม" เป็นคนละปุ่ม คนละไอคอนเสมอ:** ล็อกสี = สวอตช์ในแถว "วันนี้อยากใส่สีอะไร?" ผลคือคุมสีของ**ชุดที่แนะนำ**; ล็อกธีม = ปุ่มที่ Header ผลคือคุม**พื้นหลังหน้าเว็บ**เท่านั้น ห้ามวางสองปุ่มนี้ติดกันหรือใช้ไอคอนคล้ายกัน เพราะเป็นคนละแนวคิดที่ผู้ใช้สับสนได้ง่าย (มาจากคำถามที่ต้องแยกให้ชัดตอนออกแบบสเปก)
- **[เพิ่ม P4-D] ปิด modal จัดกลุ่มสีแล้วต้องกลับไปจุดเดิมเสมอ:** ไม่ว่าจะเปิดจากแถว "วันนี้อยากใส่สีอะไร?" หรือฟอร์มเพิ่ม/แก้ไขชิ้นเสื้อผ้า การเลือกเฉดสีใน modal ต้องปิด modal และใช้ค่านั้นในจุดที่เปิดมาทันที (ไม่ใช่แค่ปิด modal เฉยๆ แล้วให้ผู้ใช้กลับไปเลือกซ้ำ) รองรับ Escape และแตะนอก modal เพื่อปิดโดยไม่เลือกด้วย

## 7B. Micro-copy สำหรับ state ที่เปลี่ยนแบบเงียบ (สำคัญ)
ทุกครั้งที่ระบบเปลี่ยนสถานะให้ผู้ใช้เองโดยไม่ได้กด ต้อง **มี label/ข้อความบอก** ไม่ให้ผู้ใช้เดา:
- **ชุดตัวอย่าง (sample data):** การ์ด/ชิ้นที่ seed ต้องมีป้าย **"ตัวอย่าง"** ชัดทุกใบ + แถบบนสุดครั้งแรก: "นี่คือชุดตัวอย่างให้ลองเล่น เพิ่มเสื้อผ้าของคุณเพื่อดูชุดจากตู้จริง" + ปุ่ม "ล้างตัวอย่าง"
- **Auto mode switch:** เมื่อระบบเปิดโหมดให้อัตโนมัติ (ตู้ไม่พอ -> เด้งไป "สีที่เราแนะนำ") ต้องมีข้อความ inline ที่ตัวสลับ: "ตู้ยังมีของไม่พอจัดชุด เลยแสดง 'ไอเดียสีที่แนะนำ' ให้ก่อน" (ไม่สลับเงียบ)
- **โหมดถูกจำค่า:** ถ้าคืนค่าโหมดล่าสุดจาก localStorage ให้ผู้ใช้เห็นว่าตัวสลับอยู่โหมดไหน (สถานะ active ชัด) ไม่ใช่เดา
- **ทรงถูกแทนด้วยทรงเริ่มต้น (unknown shape):** หมายเหตุเล็กที่ช่องนั้น "ทรงเดิมไม่พร้อมใช้งาน แสดงทรงเริ่มต้นแทน" ไม่เปลี่ยนเงียบ
- **บันทึกอัตโนมัติลงเครื่อง:** ครั้งแรกที่เพิ่มของ บอกครั้งเดียวว่า "บันทึกไว้ในเครื่องนี้เท่านั้น" (คุมความคาดหวังเรื่องข้อมูลข้ามเครื่อง)
- **เจนชุดใหม่ทับของเดิม:** ก่อน/ขณะแทนแบตช์ ให้ feedback ว่า "สร้างชุดใหม่แล้ว" (กันงงว่าทำไมการ์ดเปลี่ยน)
- **[เพิ่ม P4-C] ธีมพื้นหลังเปลี่ยนเอง:** ครั้งแรกที่พื้นหลังขยับตามชุดใหม่ ต้องมีข้อความอธิบายครั้งเดียว (เช่น "พื้นหลังจะขยับสีตามชุดที่แนะนำ กดล็อกถ้าอยากให้หยุดที่สีนี้") ไม่ปล่อยให้ผู้ใช้เข้าใจว่าเป็นบั๊ก
- **[เพิ่ม P4-C] กดล็อก/ปลดล็อกธีม:** ต้องมีข้อความยืนยันทุกครั้ง ("ล็อกพื้นหลังไว้ที่สีนี้แล้ว" / "ปลดล็อกแล้ว พื้นหลังจะขยับตามชุดใหม่อีกครั้ง") เหมือนกับกฎเดิมของการล็อก/ปลดล็อกสี (AF1)
- **[เพิ่ม P4-B] Swap ที่ถูกจำกัดเพราะสีล็อก:** ปุ่มที่ถูกป้องกันต้องมี hint ที่**ต่างจาก**ข้อความ "มีชิ้นเดียวในหมวดนี้" เดิม เช่น "ต้องคงสีที่ล็อกไว้ในชุดนี้" ไม่ให้ผู้ใช้เข้าใจผิดว่าตู้มีของหมวดนั้นแค่ชิ้นเดียว
- **[เพิ่ม P4-B] เลือกสีแนะนำตอน swap หมดตัวเลือก:** ข้อความกำกับต้องชัดว่านี่เป็น "แนวทาง" ไม่ใช่การเปลี่ยนชุดจริง เช่น "สีที่น่าจะเข้ากับชุดนี้เพิ่ม (ยังไม่มีชิ้นนี้ในตู้)"
- **[เพิ่ม P4-D] เลือกเฉดจาก modal จัดกลุ่มสี:** ปิด modal พร้อมข้อความยืนยันสั้นๆ ที่จุดเดิม (เช่น "ล็อกสีนี้แล้ว" หรือ "ตั้งเป็นสีของชิ้นนี้แล้ว") ตามกฎเดียวกับการเลือกสีจากแถวปกติ ไม่ใช่ปิด modal เฉยๆ
หลัก: **no silent state change** ทุกการเปลี่ยนที่ระบบทำเอง = มองเห็นได้ + อธิบายสั้นๆ

## 8. System states (สรุปจาก 7C ผูกกับ view)
Empty / Loading(คำนวณแบตช์) / Insufficient / No-match / Storage-blocked / **Unknown-shape** / Deleted-garment(favorite snapshot) / Single-item(swap disabled) / All-neutral / Large-wardrobe / Reduced-motion / Shared-empty / Favorites-full
*(ตัด Image-error และ Quota-full ออกจากรายการหลัก เพราะเลิกอัปโหลดรูปแล้ว ข้อมูลต่อชิ้นเหลือไม่กี่สิบไบต์)*
- ทุกสถานะต้องมี "ข้อความ + ทางออก" ไม่ปล่อยจอว่าง/ค้าง

**เพิ่มจากเฟส 4 (System Overhaul):**
- **Color-locked-single-holder (swap disabled)** [P4-B]: หมวดเดียวที่ถือสีล็อก ตัวเลือกในวงหมดพอดี ต่างจาก Single-item ตรงที่สาเหตุคือสีล็อก ไม่ใช่ตู้มีของน้อย ต้องแยกข้อความ (§7B)
- **Swap-ring-exhausted-with-suggestion** [P4-B]: วนของในตู้ครบแล้ว ไม่มีตัวเลือกเพิ่ม แต่ยังมีสีแนะนำเชิงทฤษฎีให้ดู (ไม่ใช่ของจริง)
- **Theme-locked / Theme-unlocked** [P4-C]: สถานะคู่ของปุ่มล็อกธีม ต้องมองเห็นได้ชัดว่าอยู่สถานะไหน (เหมือนปุ่ม toggle อื่นในระบบ)
- **Missing-category-collapsed** [P4-B]: การ์ดที่ไม่มีของครบทุกหมวด ต้องยุบช่องว่างอย่างสม่ำเสมอ ไม่ทำให้การ์ดสูง/เตี้ยไม่เท่ากันจนดูเหมือนบั๊ก (เชื่อมกับกฎการ์ดยืดเท่ากันเดิมใน §10 ของสเปกหลัก)
- **Color-modal-source-variant** [P4-D]: modal เดียวกันแต่แหล่งข้อมูลต่างกันตามทางเข้า (ของในตู้ vs พรีเซ็ตทั้งชุด) ต้องไม่ให้ผู้ใช้สับสนว่าทำไมรายการสีที่เห็นไม่เหมือนกันในสองที่ที่หน้าตาคล้ายกัน (แนะนำ subtitle สั้นๆ บอกแหล่งข้อมูล เช่น "จากตู้ของคุณ" กับ "สีทั้งหมดที่เลือกได้")
- **Color-modal-empty-bucket** [P4-D]: กลุ่มโทนที่ไม่มีเฉดในแหล่งข้อมูลนั้นเลย ไม่แสดงกลุ่มนั้นในรายการ (ไม่ใช่โชว์กลุ่มว่างเปล่า)

## 9. Accessibility & usability
- **ไม่สื่อด้วยสีอย่างเดียว:** ทุกสวอทช์/ช่องมีชื่อสี + hex + ชื่อ role/rule กำกับ
- คอนทราสต์ตัวอักษร/องค์ประกอบผ่านเกณฑ์; สีแบรนด์ (แดง) แยกจากสวอทช์ข้อมูลชัด (มีกรอบ/ป้าย)
- ปุ่ม < > และแตะการ์ด: เป็น control ที่โฟกัสด้วยคีย์บอร์ดได้ + aria-label; carousel รองรับ Enter/Space
- Touch target >= 44px; รองรับ swipe และปุ่ม (ไม่บังคับ gesture อย่างเดียว)
- prefers-reduced-motion: ตัด pan/แอนิเมชั่น
- ข้อความสถานะอ่านได้ด้วย screen reader (aria-live สำหรับผลลัพธ์/แจ้งเตือน)
- **[เพิ่ม P4-B] ป้าย "แนะนำ" บน swap ต้องประกาศให้ screen reader ด้วย ไม่ใช่แค่ badge ที่เห็นด้วยตา** เช่น `aria-label` ต่อท้ายว่า "แนะนำ เข้ากับชุดนี้ดีที่สุด" ไม่ใช่พึ่งสีตัวอักษร/ไอคอนอย่างเดียว
- **[เพิ่ม P4-B] ไอคอนล็อกสีบนปุ่ม Swap ต้องมี label อธิบายเหตุผล** ไม่ใช่แค่ไอคอนเฉยๆ (เช่น aria-label "ล็อกไว้เพราะต้องคงสีที่เลือกวันนี้ในชุดนี้")
- **[เพิ่ม P4-C] การเปลี่ยนพื้นหลังตามธีมไดนามิกต้องเคารพ prefers-reduced-motion เหมือนกับ pan ของการ์ด:** ปกติไล่สี (crossfade), reduced-motion สลับทันที ไม่มีการไล่
- **[เพิ่ม P4-C] ปุ่มล็อกธีมต้องมีสถานะที่ผ่านคอนทราสต์ชัดทั้งสองสถานะ** (ล็อก/ไม่ล็อก) ไม่ใช้แค่สีอย่างเดียวในการบอกสถานะ (มีไอคอน/ข้อความกำกับ)
- **[เพิ่ม P4-D] modal จัดกลุ่มสีต้อง trap focus, ปิดด้วย Escape, และคืน focus กลับไปที่ปุ่มที่เปิดมันตอนปิด** (มาตรฐาน modal a11y ทั่วไป ยังไม่เคยมี modal ในระบบนี้มาก่อน จึงต้องกำหนดไว้ชัดตั้งแต่ต้น)
- **[เพิ่ม P4-C, ข้อจำกัดที่ต้องส่งต่อ ui-design] ป้ายชื่อ/hex ของแต่ละชิ้นต้องยังอ่านได้แม้ทรงเสื้อผ้าซ้อนทับกันตามสไตล์ Collage Art:** ห้ามให้ป้ายอยู่ในโซนที่ถูกทรงอื่นทับจนอ่านไม่ออก เป็นข้อจำกัดที่ผูกกับกฎ "ไม่สื่อด้วยสีอย่างเดียว" เดิม ไม่ใช่แค่เรื่องความสวยงาม

## 10. UX decisions & rationale
- **Results อยู่บนสุด ไม่ใช่ตู้:** ตรงเป้า "แนะนำให้ทันที" (G1) ลดขั้นก่อนเห็นคุณค่า
- **โหมด default อัตโนมัติ:** ลดภาระตัดสินใจ; ตู้ว่างก็ยังเห็นผล (idea)
- **แยก "เลื่อนดู" ออกจาก "เจนใหม่":** กันผู้ใช้เผลอสร้างชุดใหม่ทั้งที่แค่อยากดูของเดิม (ตามที่ผู้ใช้ระบุ)
- **ไม่โชว์คะแนน:** คงจุดยืน "ไม่ตัดสินการแต่งตัว" ใช้สัดส่วนสี + คำแนะนำแทน
- **Color Role นำการจัดชุด:** ทำให้คำแนะนำอ่านเป็น "หน้าที่ของสี" ไม่ใช่ตัวเลของศา ผู้ใช้เข้าใจง่ายกว่า
- **[P4-B] ไอคอนล็อกสีบน Swap แสดงตลอดเวลา ไม่ใช่แค่ตอนกดโดนบล็อก:** เลือก progressive disclosure ที่บอกเหตุผลล่วงหน้า แทนที่จะให้ผู้ใช้ลองกดแล้วค่อยเจอ error เพราะสอดคล้องกับกฎ "ไม่ปล่อยให้ผู้ใช้เดา" (§7B) ที่ยึดมาตั้งแต่เฟส 1
- **[P4-B] ป้าย "แนะนำ" ผูกกับตำแหน่งในวง ไม่ใช่ UI แยกถาวร:** เลือกความเรียบง่ายกว่า (Simplicity First จาก `working-guidelines.md`) เพราะการเพิ่ม UI element แยกสำหรับสิ่งที่ ring cycling เดิมโชว์ได้อยู่แล้วเป็นการเพิ่มความซับซ้อนที่ไม่จำเป็น
- **[P4-C] "ล็อกสี" กับ "ล็อกธีม" ต้องแยกกันอย่างเด็ดขาดทั้งตำแหน่งและไอคอน:** ป้องกันความสับสนระหว่างสองแนวคิดที่ฟังดูคล้ายกัน (ทั้งคู่มีคำว่า "ล็อก") แต่คุมคนละอย่าง (สีของชุด vs สีพื้นหลังหน้าเว็บ) ตัดสินใจตอน grill สเปกร่วมกับผู้ใช้
- **[P4-D] modal จัดกลุ่มสีใช้แหล่งข้อมูลต่างกันตามทางเข้า แทนที่จะใช้แหล่งเดียวกันทั้งคู่:** ทางเข้าจากแถวสีวันนี้ตอบคำถาม "มีอะไรอยู่แล้ว" ส่วนทางเข้าจากฟอร์มเพิ่มชิ้นเสื้อผ้าตอบคำถาม "จะเลือกสีอะไรดี" เป็นคำถามคนละแบบ ถ้าใช้แหล่งเดียวกัน (เฉพาะของในตู้) ทางเข้าหลังจะไม่มีประโยชน์เลยตอนตู้ว่าง/ของน้อย (พบระหว่างรอบ grill สเปก)
