# รอบ 3: optimizer v2 กับ input ที่ไม่เคยเห็น

วันที่: 2026-09-17
วิธี: subagent ของ Claude Code ไม่ใช้ API key
ตัว product ที่ทดสอบ: `optimizer.md` **v2** ซึ่งเพิ่มกฎข้อ 0 (triage ก่อนแปลง) และกฎข้อ 11 (อนุภาคภาษาไทย)

## ทำไมต้องใช้ input ชุดใหม่

v2 เกิดจากการสังเกต P02 และ F16 ใน `RUN-2-RESULTS.md` ถ้าเอาสองข้อนั้นมาวัด v2 ก็คือการเอาสมมติฐานมาทดสอบกับข้อมูลที่สร้างสมมติฐานนั้นขึ้นมา ซึ่งไม่ได้พิสูจน์อะไร

รอบนี้จึงใช้ **9 input ที่ไม่เคยถูกให้คะแนนในรอบไหนเลย** และตัวอย่างใน prompt ของ v2 เองก็ใช้ข้อความที่แต่งขึ้นใหม่ ไม่ได้หยิบจาก `inputs.json`

แบ่งเป็นสองกลุ่มโดยตั้งใจ:
- **6 ข้อที่กำกวมหรือเป็น fragment** (R01, R03, R05, P03, F10, P05) คือกลุ่มที่กฎข้อ 0 มุ่งแก้
- **3 ข้อที่ครบสมบูรณ์** (F23, R19, F25) คือ regression check ว่า v2 ไม่ทำของที่เคยทำได้ดีพัง

## confound ที่เจอกลางทาง และ arm ที่เพิ่มเข้ามาเพื่อแก้

พอเห็นผลระหว่างรัน ผมสังเกตว่า prompt ของสอง arm **มีความแรงของคำสั่งไม่เท่ากัน**

- arm `D` (v2, เส้นทาง fragment) มีประโยคว่า `Do not begin the task and do not assume what is missing. Ask the user these questions first` ซึ่งเป็นคำสั่งห้ามตรงๆ
- arm `E` ตาม pre-registration มีแค่ `ถ้ามีอะไรไม่ชัด ถามก่อนตอบ` ซึ่งเป็นเงื่อนไขอ่อนๆ

ถ้าเทียบสอง arm นี้ตรงๆ สิ่งที่วัดได้อาจเป็นแค่ "คำสั่งห้ามแรงกว่าคำสั่งเชิญชวน" ไม่ใช่ "การ optimize มีคุณค่า" ซึ่งเป็นคนละเรื่องกับที่ product อ้าง

จึงเพิ่ม **arm `E'`** เป็น control หลังบ้าน: ภาษาไทยดิบ + ประโยคไทยที่แรงเท่ากับ D คือ

> ถ้าข้อมูลในข้อความนี้ไม่พอที่จะลงมือ ห้ามเริ่มทำและห้ามเดาส่วนที่ขาด ให้ถามกลับก่อน

`E'` ไม่ได้อยู่ใน pre-registration จึงเป็น post-hoc control ไม่ใช่ baseline ที่ล็อกไว้ รายงานทั้งสองค่า

## สองคำตัดสินที่ไม่ตรงกัน

**เทียบกับ baseline ที่ล็อกไว้ (E): margin = +15.8 pp**

ตามตาราง `PREREGISTRATION.md` นี่คือช่วง `>= +15 pp` ซึ่งแปลว่า **สร้าง**

**เทียบกับ control ที่ความแรงคำสั่งเท่ากัน (E'): margin = +11.8 pp**

ตกในช่วง `+5 ถึง +15 pp` ซึ่งแปลว่า **ยังไม่สรุป**

ผลต่างระหว่างสองตัวเลขนี้ คือ 4 pp ที่หายไปเมื่อเปลี่ยนแค่ประโยคไทยต่อท้ายให้แรงขึ้น นั่นคือส่วนของคะแนนที่ **ไม่ได้มาจากการแปลหรือการ optimize** แต่มาจากการสั่งห้ามอย่างชัดเจน ซึ่งผู้ใช้พิมพ์เองได้ฟรี

ผมถือว่าค่าที่ควรใช้ตัดสินใจคือ **+11.8 pp ยังไม่สรุป** ไม่ใช่ +15.8 pp เพราะ E ถูกออกแบบไว้ตอนที่ยังไม่รู้ว่า D จะมีประโยคห้ามอยู่ข้างใน พอรู้แล้วว่ามันไม่สมมาตร การยึดตัวเลขที่สูงกว่าคือการเลือกกติกาให้เข้าข้างตัวเอง

## ที่ D ชนะจริง และชนะซ้ำได้ทั้งสอง baseline

ทั้ง E และ E' แพ้สองข้อเดียวกัน แปลว่าไม่ใช่ความบังเอิญของการรันครั้งเดียว

**F23 "อยากอ่านชีวะประวัติของคนเก่งๆหาให้อ่าน1คนทีครับ"**

ต้นฉบับไทยบอกว่า "1 คน" ชัดเจน แต่ทั้ง E และ E' ตอบด้วยการเสนอคนหลัก 1 คนแล้วต่อท้ายด้วยตัวเลือกอีก 3 คน ส่วน D ได้ prompt ว่า `Pick exactly one person, name them, and name the biography to read.` แล้วตอบมา 1 คนเป๊ะ

นี่คือกฎข้อ 9 (ระบุรูปร่างของผลลัพธ์) ทำงานจริง **การเขียนข้อกำหนดออกมาเป็นคำสั่งตรงๆ ได้ผลกว่าการพูดถึงมันในประโยค** และนี่เป็นสิ่งที่ประโยคต่อท้ายภาษาไทยให้ไม่ได้ เพราะมันไม่ได้แตะโครงสร้างของคำขอ

**R01 "ทำอะไรได้บ้างครับในโมเดลนี้"**

ทั้ง E และ E' อ่าน "โมเดลนี้" ว่าหมายถึงตัวเอง แล้วร่ายความสามารถของ Claude ออกมายาวเหยียดพร้อมชื่อผลิตภัณฑ์ที่ผู้ใช้ไม่เคยพูด ส่วน D ซึ่งระบุไว้ชัดว่า referent หายไป ถามกลับอย่างเดียว

เป็นผลข้างเคียงที่ดีของการถอดบริบทการสนทนาออก แต่ดูข้อถัดไปประกอบ เพราะเหรียญนี้มีอีกด้าน

## ที่ D แพ้แบบที่ checks มองไม่เห็น

ทั้งสามข้อนี้ D ได้คะแนนเต็ม แต่คำตอบแย่กว่าจริง

**F10 "ทำรายละเอียดสเปส X"** ฝั่งไทยทั้ง E และ E' เดาออกว่า "สเปส X" น่าจะคือ SpaceX แล้วเสนอเป็นตัวเลือกแรกพร้อมบอกว่าพร้อมเขียนให้ทันที ส่วน pipeline แปลเป็นตัวอักษร `"X"` เฉยๆ **ความเป็นไปได้ว่าคือ SpaceX หายไปตั้งแต่ขั้นแปล** executor ของ D จึงไม่มีทางเสนอได้ นี่คือปัญหาเดียวกับ "ล่ะ" ใน F16 รอบที่แล้ว และเป็นครั้งที่สองที่เจอ **การแปลงเป็นอังกฤษทำให้เบาะแสที่มีอยู่ในตัวสะกดไทยหายไป**

**F25 "วิเคราะห์ตัว Qualcomm"** E และ E' ตอบเป็นภาษาไทย ส่วน D ตอบเป็นภาษาอังกฤษ เพราะ prompt ที่ส่งไปเป็นอังกฤษล้วน ผู้ใช้เขียนคำถามมาเป็นไทย **ถ้าผู้ใช้อ่านอังกฤษไม่คล่อง นี่คือความเสียหายเต็มๆ** `checks` ของ F25 ไม่ได้ตรวจภาษา จึงให้ 2/2 เท่ากัน ทั้งที่คำตอบใช้งานได้ไม่เท่ากัน

**R19 หลัก Karpathy** D ถามกลับอย่างเดียว ส่วน E และ E' ถามกลับ **พร้อมเสนอความรู้ที่มีค่า** เช่น pattern progressive disclosure และข้อสังเกตว่าข้อความไทยกิน token มากกว่าอังกฤษหลายเท่า ซึ่งตรงกับเป้าหมายของผู้ใช้พอดี เส้นทาง fragment ของ v2 สั่งว่า `Do not begin the task` ซึ่ง **ปิดกั้นการช่วยเหลือบางส่วนที่มีประโยชน์ไปด้วย**

## อคติของชุดทดสอบนี้ ที่ต้องพูดก่อนใครจะเชื่อตัวเลข

1. **ชุดทดสอบเอียงเข้าข้าง v2 โดยการออกแบบ** ผมเลือก 6 ใน 9 ข้อให้เป็น fragment เพราะนั่นคือสิ่งที่กฎข้อ 0 มุ่งแก้ ถ้าสุ่มจาก 40 ข้อจริงๆ สัดส่วน fragment จะไม่สูงขนาดนี้
2. **`checks` ของข้อพวกนี้ให้รางวัลกับการถามกลับ** หลายข้อเขียนตรงๆ ว่า "output ถามกลับ... แทนที่จะสมมติเอง" ส่วนกฎข้อ 0 สั่งให้ถามกลับ เกือบจะเป็นการวัดตัวเองด้วยไม้บรรทัดของตัวเอง
3. **v2 จัด 7 ใน 9 เป็น fragment** รวมสองข้อที่ผมจัดว่าครบ ถ้าแนวโน้มนี้จริง v2 ไม่ได้ triage แต่เปลี่ยน default เป็น "ถามไว้ก่อน" ซึ่งเป็นพฤติกรรมที่ประโยคไทยหนึ่งประโยคทำได้เหมือนกัน
4. **ผมให้คะแนนเอง ไม่ blind** และมีสองจุดที่เป็นดุลพินิจ (R03 check 2, F23 check 1) ซึ่งทั้งคู่ตัดสินไปทางลบกับ E จุดที่ปลอบใจได้คือ F23 ให้ผลซ้ำใน E' ด้วย จึงไม่ใช่การตัดสินครั้งเดียว
5. n = 9, รัน 1 ครั้งต่อ arm, ยังไม่มี arm A, B, C, F, และ input ทั้งหมดมาจากผู้ใช้คนเดียว

## สรุป

**v2 ดีกว่า v1 จริง** v1 ได้ margin 0.0 pp ในรอบ 2 ส่วน v2 ได้ +11.8 pp เทียบกับ control ที่ยุติธรรม การเพิ่ม triage แก้ปัญหาที่รอบ 2 ตรวจพบได้จริง

**แต่ยังไม่ถึงเกณฑ์สร้าง** และเหตุผลสำคัญกว่าตัวเลข: คะแนนที่ได้เพิ่มมาส่วนใหญ่มาจากสองกลไกที่ **ไม่ต้องมีเว็บไซต์ก็ทำได้**

- สั่งห้ามให้ชัด (`ห้ามเริ่มทำถ้าข้อมูลไม่พอ`) ผู้ใช้พิมพ์เองได้ฟรี วัดได้จากผลต่าง E กับ E'
- ระบุรูปร่างผลลัพธ์ให้ชัด (`เอา 1 คน ชื่อคนและชื่อหนังสือ`) ผู้ใช้ก็พิมพ์เองได้ ถ้ารู้ว่าต้องพิมพ์

ส่วนที่ผู้ใช้ทำเองไม่ได้ คือการรู้ล่วงหน้าว่าคำขอของตัวเองขาดอะไร ซึ่งเป็นคุณค่าจริงแต่ยังวัดไม่ได้จากชุดนี้

**และ v2 สร้างความเสียหายใหม่ที่ v1 ไม่มี** คือการตอบกลับเป็นภาษาอังกฤษให้คนที่เขียนคำถามมาเป็นไทย และการห้ามช่วยเหลือบางส่วนที่มีประโยชน์ สองอันนี้ต้องแก้ก่อนคิดเรื่องสร้างต่อ

## ถ้าจะไปต่อ ควรทำอะไร

1. **บังคับภาษาของคำตอบ** เพิ่มกฎว่า `<optimized>` ต้องปิดท้ายด้วยคำสั่งให้ตอบเป็นภาษาไทย เมื่อ input เป็นภาษาไทย นี่แก้ง่ายและได้ผลทันที
2. **ผ่อนเส้นทาง fragment** เปลี่ยนจาก `Do not begin the task` เป็นอนุญาตให้ตอบส่วนที่ตอบได้ พร้อมระบุว่าส่วนไหนต้องรอคำตอบ เพราะ R19 แสดงว่าการห้ามเด็ดขาดทิ้งคุณค่าไปเปล่าๆ
3. **เก็บชื่อเฉพาะที่สะกดแบบไทยไว้** F10 กับ F16 เป็นหลักฐานสองครั้งแล้วว่าการทับศัพท์ไทยมีเบาะแสที่ตายตอนแปล ควรมีกฎให้เก็บคำไทยต้นฉบับไว้ในวงเล็บ
4. **ทดสอบบนชุดที่ไม่เอียง** สุ่ม 20 ข้อจาก 40 โดยไม่เลือกว่าเป็น fragment หรือไม่ และใช้ E' เป็น baseline ตั้งแต่ต้น
