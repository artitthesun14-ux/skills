## ข้อสังเกตที่สำคัญกว่าตัวเลข

### D ชนะตอนไหน แพ้ตอนไหน

ชนะข้อเดียว R12 ซึ่งเป็น**คำถามที่ครบอยู่แล้ว** แค่เขียนรุงรัง พอจัดให้สะอาด model ตอบได้เลยแทนที่จะถามกลับ

แพ้ข้อเดียว P02 ซึ่งเป็น **fragment** ("เป็นสต็อครองเท้าหลาย SKUมากๆ") arm E ถามกลับ 5 ข้อ ส่วน arm D ได้ prompt ว่า `Handle a shoe inventory that contains a very large number of SKUs.` ซึ่งอ่านเหมือนคำสั่งที่สมบูรณ์ model เลยลงมือออกแบบ schema ให้ทันทีโดยเดาเอาเองว่าผู้ใช้ต้องการ data model

นี่คือรูปแบบที่ควรจำ: **การ optimize ทำให้ fragment ดูเหมือนคำสั่งที่สมบูรณ์ ซึ่งชวนให้ model เดาแทนที่จะถาม** เป็นผลเสียที่เกิดจากตัว product เอง

### ข้อมูลหายจากการแปล: อนุภาคภาษาไทย

F16 ต้นฉบับคือ "Pwr **ล่ะ**" คำว่า "ล่ะ" บอกว่ากำลังเทียบกับอะไรบางอย่างที่พูดไว้ก่อนหน้า

pipeline แปลเป็น `Address the topic "Pwr".` ซึ่ง**อนุภาคหายไปทั้งหมด** ผลคือ arm E ถามว่า "ก่อนหน้านี้กำลังเทียบกับตัวไหนอยู่" ส่วน arm D ถามได้แค่ว่า PWR คืออะไร เพราะไม่เหลือร่องรอยว่ามีการเปรียบเทียบอยู่

pipeline เอา "ล่ะ" ไปไว้ใน `open_questions_th` ซึ่งดีกว่าทิ้งเฉยๆ แต่ขัดกฎข้อ 1 และ 3 ที่ว่าสิ่งที่ผู้ใช้พูดต้องอยู่ใน `<optimized>` และ `<optimized>` ต้องยืนได้เอง

ถ้านับเคร่ง invariant = 25/27 = **92.6% ตกเกณฑ์ 95%** ถ้านับหลวม (ถือว่าอนุภาคไม่ใช่ requirement) = 26/27 = 96.3% ผ่าน ผมตัดสินไม่ได้แบบไม่ลำเอียง จึงรายงานทั้งสองค่า

แต่ไม่ว่านับแบบไหน **สิ่งที่สังเกตได้จริงคือ arm E ถามเรื่องการเปรียบเทียบได้ arm D ถามไม่ได้** นั่นคือข้อมูลที่หายไปจริง

## ข้อจำกัดที่ยังเหลือ

- n = 9 จาก 40 และรันครั้งเดียว ไม่ใช่ 3 ครั้งตามที่ pre-registration กำหนด
- ยังไม่มี arm A, B, C, F จึงยังตอบไม่ได้ว่าการแปลเป็นอังกฤษจำเป็นไหม
- **ผมให้คะแนนเอง ไม่ blind** แม้ checks จะเขียนไว้ล่วงหน้าและค่อนข้างเป็นกลไก
- model ที่ใช้เป็นของ session นี้ ไม่ใช่ `claude-opus-5` ตามที่ harness ตั้งไว้

ด้วย n = 9 ผลเสมอ 0.0pp ไม่ได้พิสูจน์ว่า "ไม่มีผลต่างเลย" แต่มันพิสูจน์ว่า **ไม่มีผลต่างขนาดใหญ่พอที่จะเห็นได้ง่ายๆ** ซึ่งเพียงพอที่จะไม่ลงทุนสร้าง product ต่อ

## ข้อเสนอถ้าจะไปต่อ

ตัวเลขบอกว่า optimizer ในรูปแบบปัจจุบันไม่ชนะประโยคเดียว แต่บอกด้วยว่ามันช่วยตอนไหน: **input ที่ครบแล้วแต่เขียนรุงรัง**

ทางที่มีเหตุผลกว่าการทิ้งทั้งหมด คือเปลี่ยน optimizer ให้**แยกสองกรณีก่อน**:

1. input ครบพอจะลงมือได้ → optimize เต็มรูปแบบ (นี่คือที่มันชนะ)
2. input เป็น fragment → **อย่าแปลงเป็นคำสั่ง** ให้คืนคำถามกลับเป็นภาษาไทยอย่างเดียว เพราะการแปลงทำให้แย่ลง (นี่คือที่มันแพ้)

ข้อ 2 คือสิ่งที่ข้อมูลชี้ และมันขัดกับสมมติฐานตั้งต้นที่ว่า "แปลงทุก input ให้เป็น English instruction" ถ้าจะทดลองรอบใหม่ ควรทดสอบ optimizer เวอร์ชันที่ปฏิเสธที่จะแปลง fragment
